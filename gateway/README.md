# API gateway

Independent Go module and Docker build context for the local НетДосуга ticket office. Run `go test ./...` or `docker build -t netdosuga-gateway .`; Docker runs the tests before compiling. Full-stack startup belongs to `platform/`.

Swagger UI is embedded at `/swagger/` (`/swagger` redirects there). Its pinned local JavaScript and CSS need no CDN, npm build or additional container. `/openapi.yaml` serves the exact canonical `api/openapi.yaml` bytes as `application/json` because this OpenAPI document uses JSON syntax. Use Try it out on `POST /api/v1/auth/login` first; the browser manages the HttpOnly `nd_session` cookie for subsequent same-origin calls and `POST /api/v1/auth/logout`. Cookie values cannot be entered through Swagger's Authorize dialog. Payments and refunds remain mock operations. Vendor sources, version, license and checksums are recorded in `swagger/vendor/README.md`.

Startup requires `APP_ENV=local` and `MOCK_MODE=true`. Defaults: `HTTP_ADDR=:8080`, `ORDER_GRPC_ADDR=order-service:50051`, `ORDER_GRPC_TIMEOUT=3s`, `IDENTITY_BASE_URL=http://identity-service:8084`. The timeout must be positive. OTLP uses `OTEL_EXPORTER_OTLP_ENDPOINT=jaeger:4317`; service name defaults to `api-gateway`.

The embedded interface at `/` needs no npm build. Anonymous visitors browse the catalogue. Actual identity-service sessions provide customer, vendor and moderator access. `/api/v1/auth/register`, `/login`, `/session` and `/logout` proxy identity operations; login and registration put the opaque token only in the HttpOnly, SameSite=Lax `nd_session` cookie. `COOKIE_SECURE=true` enables Secure for a TLS deployment. Explicit foreign Origin or cross-site Fetch-Site requests are rejected for mutations; JSON bodies are required. Local CLI requests may omit Origin. The local seed-account disclosure does not authenticate or change identity.

Shop routes form a fixed allowlist of gRPC commands. Cookie sessions become outgoing Authorization metadata; incoming `X-Demo-Actor` and Authorization headers are not identity sources. Order-service independently validates sessions and roles. Only catalogue city/category query fields are forwarded. JSON object bodies are bounded to 64 KiB. Checkout requires an idempotency key. Shop calls have at least a five-second deadline so bounded payment-mock failures can return. All payments and refunds are explicitly simulated; no bank-card fields are collected. UI prices are rubles; the API uses integer kopecks.

Shop responses include `demo:true` and `trace_id`; domain HTTP status codes pass through, transport failures return 502/504. Replica headers expose serving instances. The collapsed developer panel preserves the last mutation trace across subsequent read refreshes. Structured request/response logs and span attributes use a recursive allowlist, at most three array items and 2048 bytes, excluding credentials, personal text and ticket codes. Auth bodies are never logged.

The isolated legacy `/api/v1/demo/orders` accepts scenarios success, delay, error and timeout and retains its original contract. `/healthz` reports liveness; `/readyz` checks order-service gRPC health; `/metrics` exposes HTTP and runtime metrics. W3C trace context propagates through gRPC and identity HTTP. SIGTERM bounds shutdown and trace flush. The runtime image uses UID 10001. `api/openapi.yaml` describes HTTP routes; `api/order.proto` remains identical to order-service.
